## 🧭 Το project με μια ματιά

Full-stack εργαλείο που **ενοποιεί δύο ελληνικά δημόσια μητρώα**:

- **Διαύγεια** — αποφάσεις/δαπάνες του Δημοσίου
- **ΚΗΜΔΗΣ** — Κεντρικό Ηλεκτρονικό Μητρώο Δημοσίων Συμβάσεων (προμήθειες)

Ο χρήστης διαλέγει έναν φορέα και βλέπει στατιστικά, αναλυτικές πράξεις (paginated), εξαγωγή σε CSV/PDF, και — το πιο ενδιαφέρον — την **«αλυσίδα» μιας σύμβασης**: Αίτημα → Προκήρυξη → Ανάθεση → Σύμβαση → Πληρωμή, με cross-validation ποσών.

**Stack**

| Layer | Τεχνολογίες |
|---|---|
| Backend | Node.js, Express 5, MongoDB (Atlas) |
| Frontend | React, Vite |
| Πηγές δεδομένων | Diavgeia OpenData API, ΚΗΜΔΗΣ OpenData API |

**Ροή δεδομένων (pipeline):** `download → normalize → upsert (ΑΔΑ = κλειδί) → incremental refresh → paginated/aggregate queries`.

## 🏛️ Αρχιτεκτονικές αρχές

Αρχές που κρατήθηκαν σεβαστές σε όλο το review:

- **Group πάντα με ΑΦΜ**, ποτέ με ονόματα (τα ονόματα είναι αναξιόπιστα/διπλογραμμένα).
- **`organizationUid` ≠ ΑΦΜ** — δύο διαφορετικά αναγνωριστικά.
- **Αρνητικά ποσά = ακυρώσεις** (υπαρκτά δεδομένα, όχι σκουπίδια).
- **Καθαρές συναρτήσεις** (normalizer / filters / stats / output) **χωρίς δικτύωση** — μόνο οι orchestrators αγγίζουν τον έξω κόσμο.
- **Σταθερό contract** το `options` object σε όλη τη διαδρομή.

Κάθε διόρθωση παρακάτω σέβεται αυτές τις αρχές (π.χ. το κρίσιμο fix έγινε σε μια **καθαρή** συνάρτηση, χωρίς να μολυνθεί με I/O).

## 🔬 Μεθοδολογία του review

Δεν έγιναν «τυφλές» αλλαγές. Η προσέγγιση ήταν:

```
1. Recon        → χαρτογράφηση όλων των αρχείων, ανάγνωση κάθε module
2. Ground truth → ανάλυση του πραγματικού raw JSON (9.349 πράξεις) για να
                  καταλάβω τα ΠΡΑΓΜΑΤΙΚΑ σχήματα δεδομένων, όχι τα υποτιθέμενα
3. Εντοπισμός   → σύγκριση κώδικα vs πραγματικών δεδομένων → bugs
4. Fix          → διόρθωση σε καθαρές συναρτήσεις
5. Verify       → offline δοκιμές με πραγματική Mongo (in-memory) + το dataset
6. Regression   → parity tests: η νέα διαδρομή δίνει ΑΚΡΙΒΩΣ τα ίδια νούμερα
```

> Το βήμα #2 ήταν αυτό που ξεκλείδωσε τα πάντα: μόλις κοίταξα τι **πραγματικά** περιέχει το `extraFieldValues`, φάνηκε αμέσως το κρίσιμο bug.

## 🐞 Το κρίσιμο bug: χαμένα €15,7M

### Το σύμπτωμα
Τα συνολικά ποσά ενός φορέα ήταν **αδικαιολόγητα χαμηλά**. Το σύνολο έβγαινε **~€6,4M**.

### Η ρίζα (root cause)
Στη Διαύγεια, το ποσό μιας πράξης κρύβεται σε **διαφορετικό nested path ανά τύπο απόφασης**. Ο normalizer τα χειριζόταν σχεδόν σωστά — εκτός από έναν τύπο:

```js
// ΛΑΘΟΣ (πριν):
} else if (efv.amountWithKae && efv.amountWithKae.length > 0) {
    amount = efv.amountWithKae[0].amountWithVAT?.amount ?? 0;
    //                            └── «.amount» πάνω σε ΣΚΕΤΟ ΑΡΙΘΜΟ → undefined → 0
}
```

**Η παγίδα:** στα raw δεδομένα το `amountWithKae[i].amountWithVAT` **δεν** είναι αντικείμενο `{ amount, currency }` — είναι **σκέτος αριθμός** (π.χ. `3542.45`). Διαβάζοντας `.amount` πάνω σε αριθμό → `undefined` → `?? 0`. Έτσι **κάθε** τέτοια πράξη μηδενιζόταν σιωπηλά.

Το πραγματικό σύνολο ζει στο top-level `efv.amountWithVAT.amount`.

### Η κλίμακα
Ανάλυση στο πραγματικό dataset (9.349 πράξεις ενός φορέα):

| Μέγεθος | Τιμή |
|---|---|
| Πράξεις που μηδενίζονταν | **1.646** (17,6%) |
| Χαμένο ποσό | **€15.678.275,72** |
| Σύνολο **πριν** | €6,4M |
| Σύνολο **μετά** | **€22.061.557,92** |

### Η διόρθωση
Εξήχθη μια **καθαρή** συνάρτηση `extractCounterparty(praksi)` (κοινή για normalizer & aggregation), με σωστό path και ασφαλή fallback:

```js
} else if (efv.amountWithKae && efv.amountWithKae.length > 0) {
    // Το amountWithKae[i].amountWithVAT είναι ΑΡΙΘΜΟΣ — το σύνολο είναι στο efv.amountWithVAT.amount
    amount =
        efv.amountWithVAT?.amount ??
        efv.amountWithKae.reduce((s, line) => s + (Number(line.amountWithVAT) || 0), 0);
}
```

## ⚡ Ταχύτητα: στατιστικά μέσα στη Mongo

**Πριν:** κάθε κλήση `/stats/:afm` έφερνε **όλες** τις πράξεις του φορέα στη μνήμη του Node (~45.000 για μεγάλους φορείς), τις `normalize`-άριζε μία-μία και μετά υπολόγιζε στατιστικά. Ακριβό σε μνήμη & χρόνο.

**Μετά:** νέο module `stats-aggregate.mjs` που υπολογίζει `sum / average / median / max / min / topSponsors` **μέσα στη MongoDB** με ένα aggregation pipeline. Το ποσό υπολογίζεται inline με `$switch` πάνω στα σωστά raw paths (ίδια λογική με τον normalizer), και τα φίλτρα (τύπος, ημερομηνία, ποσό, λέξη-κλειδί, αντισυμβαλλόμενος) μπαίνουν στο `$match`.

Η δυσκολία που έπρεπε να λυθεί: **τα raw πεδία δεν είναι πάντα πίνακες** — το `person` μερικές φορές είναι σκέτο object, το `sponsor` μερικές φορές `null`. Το `$size` σκάει σε non-array, οπότε κάθε `$size` προστατεύεται με `$isArray`, ώστε η λογική να ταιριάζει **ακριβώς** με το `x && x.length > 0` του JS.

➡️ Το pipeline & το «γιατί»: [`code-highlights/02-stats-aggregation.md`](code-highlights/02-stats-aggregation.md)

## 🔒 Ασφάλεια & robustness

**1. Regex-injection / ReDoS.** Η αναζήτηση φορέα και το reverse-lookup ΑΔΑΜ έβαζαν **raw είσοδο** μέσα σε Mongo `$regex`. Κακόβουλο input (π.χ. `(a+)+`) μπορεί να προκαλέσει catastrophic backtracking. Προστέθηκε `escapeRegex()` σε κάθε τέτοιο σημείο.

**2. Απόκρυψη σφαλμάτων.** Τα endpoints είχαν ένα γενικό `catch` που γύριζε **`404 «δεν βρέθηκαν δεδομένα»`** — ακόμα κι όταν το πραγματικό πρόβλημα ήταν πτώση της βάσης. Πλέον διαχωρίζονται καθαρά:
- `404` → όντως κενό αποτέλεσμα
- `500` → πραγματικό σφάλμα (με `console.error` για διάγνωση)

**3. Μυστικά εκτός git.** Το `MONGO_URI` (ζωντανό DB credential) αποκλείστηκε μέσω `.gitignore` και αντικαταστάθηκε με `.env.example`.

➡️ Λεπτομέρειες: [`code-highlights/03-security-hardening.md`](code-highlights/03-security-hardening.md)

## 🧪 Πώς επαληθεύτηκαν όλα (χωρίς πρόσβαση στη βάση)

Το production MongoDB Atlas **δεν ήταν προσβάσιμο** από το περιβάλλον εργασίας (TLS/IP-allowlist). Αντί να δουλέψω «στα τυφλά», στήθηκε **offline pipeline επαλήθευσης**:

1. **Ephemeral Mongo** (`mongodb-memory-server`) — πραγματική μηχανή MongoDB στη μνήμη.
2. Φόρτωση του **πραγματικού** dataset (9.349 πράξεις) σε αυτήν.
3. **Parity test:** τρέχω και την παλιά in-memory διαδρομή και το νέο aggregation, και συγκρίνω **κάθε** μετρικό — με & χωρίς φίλτρα.
4. **HTTP integration test:** σηκώνω τον πραγματικό Express server και χτυπάω όλα τα endpoints.

Αποτέλεσμα parity test:

```
=== NO FILTERS ===
✅ decisionsLength   agg=9349        ref=9349
✅ withAmountLength  agg=3363        ref=3363
✅ sum               agg=22061557.92 ref=22061557.92
✅ median            agg=932         ref=932
✅ topSponsors       agg=[…]         ref=[…]   (ταυτόσημα)
=== FILTER type=Β.1.3 minAmount=1000 maxAmount=50000 ===
✅ decisionsLength   agg=1114        ref=1114
✅ sum               agg=8988430.62  ref=8988430.62
ALL GOOD ✅
```
